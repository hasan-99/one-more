# App Store and Google Play pre-submission audit — November 2026

Scope: the repository (Expo SDK 58 / React Native 0.88 app, Supabase migrations, one Edge Function), generated native projects (`expo prebuild` for Android and iOS), dependencies and licences. **Not possible from this environment:** real iPhone/Android devices, App Store Connect and Play Console access, production signing keys, a live backend. Those items are listed under "Manual steps". Policy references are to the Apple App Store Review Guidelines and Google Play Developer Program Policies as understood at the time of writing; re-check the current text when submitting.

## Verdict

**Not ready to submit yet.** Code-side blockers found in this audit are fixed. Five owner actions remain that no code change can solve (section 4): final bundle identifiers, support email and publisher details, production backend + demo accounts, applying the three migrations, and real-device testing with store-console forms.

## 4. Manual steps (owner)

**Before any build**

1. Choose the final reverse-domain identifier (for example `com.<yourdomain>.onemore`) and set `ios.bundleIdentifier` and `android.package` in `app.json`.
2. Set EAS environment variables for production: `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `EXPO_PUBLIC_SUPPORT_EMAIL` (a monitored mailbox), `EXPO_PUBLIC_DEVELOPER_NAME`, `EXPO_PUBLIC_DEVELOPER_ADDRESS`.
3. Apply migrations in order: `20261116090000_challenge_any_city.sql`, `20261117090000_security_hardening.sql`, `20261118090000_delete_my_account.sql`, `20261118091000_block_users.sql` (plus any earlier migration still unapplied). Run the pgTAP suite on a staging project first: the new SQL was tested only on a scratch database, not the full Supabase schema.
4. Deploy the web export to a production HTTPS domain; confirm the five public URLs return 200 without login and that HTTP redirects to HTTPS.
5. Verify a sending domain for Resend and set the Edge Function secrets (`RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `APP_BASE_URL`).
6. Have the Privacy Policy and Terms reviewed by a qualified lawyer (they are written from the app's actual behaviour but are not legal advice). Confirm the minimum age (16), the data region and your data-processing agreements with Supabase, Resend and Expo.

**App Store Connect** 7. Create the app with the final bundle id; add Privacy Policy URL, Support URL, Marketing URL; fill App Privacy from `PRIVACY_LABELS.md`; age rating questionnaire (expect 12+); category Sports; upload real screenshots; paste the review notes and demo credentials; set export compliance to "uses only standard encryption". 8. Build with `eas build --profile production --platform ios`, test on TestFlight, then submit.

**Google Play Console** 9. Create the app; complete Data safety, Account deletion URL (`/delete-account`), Content rating (IARC), Target audience 16+, UGC declaration, Ads = No; upload app bundle from `eas build --profile production --platform android`; run the internal test track on real devices; provide the feature graphic and screenshots. Complete the 12-tester closed test required for new personal accounts if that applies to your account type.

## 5. Evidence summary

- `npx tsc --noEmit`, `npx eslint src e2e --max-warnings=0`: clean. Unit tests: 50/50 (vitest).
- Playwright (mobile and desktop): `store-compliance.spec.ts` 20/20 (public pages EN and GL, legal links, Settings links, blocked-player list and unblock, account deletion, block in chat).
- Regression run (mobile): 47 passed, 4 failed. The same 4 failed identically on the build from before this work (`landing.spec`, `phase-02` main navigation and Greek, `phase-10-teams` guest directory): they still asserted older screens (a "Find a game" button, a public Home page, a two-button language switch) and ran without a mocked backend. The tests were updated to the current behaviour (Home is a private page that returns to sign-in; one language toggle; empty-list backend mock) and now pass on desktop and mobile.
- `expo prebuild` for Android and iOS: merged manifest, Info.plist and PrivacyInfo reviewed (permissions listed above).
- SQL: delete and block functions executed on a scratch PostgreSQL 16 (restricting foreign keys reproduced). The full migration chain could not be replayed locally because some historical migration timestamps are out of dependency order; this is a known limitation.
- `npm audit`: 0 vulnerabilities.
